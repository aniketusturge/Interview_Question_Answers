

1. What is GitHub Actions?

GitHub Actions is a CI/CD and automation platform provided by GitHub that allows you to automate workflows such as:
Build
Test
Deploy
Security scanning
Infrastructure provisioning

using YAML files stored inside the repository.

2. What is a Workflow?

A workflow is an automated process defined in a YAML file under:

.github/workflows/

Example:

name: Build Application

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4
      - run: echo "Building application"

3. What are the components of a GitHub Action workflow?

Main components:
Event (Trigger)
Workflow
Job
Step
Action
Runner

4. What is a Runner?
A runner is a server that executes workflow jobs.

GitHub-hosted runners:
-ubuntu-latest
-windows-latest
-macos-latest

Self-hosted runners:
-On-premise VM
-EC2 Instance
-Kubernetes Pod

5. What is an Action?

An Action is a reusable unit of code.

Example:

- uses: actions/checkout@v4

This action clones the repository.

6. Difference between Workflow, Job, and Step?
Workflow :Entire automation process.

Job : Collection of steps.

Step: Single task within a job.

Example:
jobs:
  build:
    steps:
      - run: npm install
      - run: npm test

Useful for:

Repository
→ Settings

env:

10. What is actions/checkout?

Checks out repository code to the runner.

- uses: actions/checkout@v4

Without it, code is not available on runner.


11. How do you pass data between jobs?

Use job outputs. A step sets an output, the job exposes it under outputs:, and downstream jobs reference it with needs.job_name.outputs.key.

jobs:
  build:
    outputs:
      version: ${{ steps.get_ver.outputs.version }}
    steps:
      - id: get_ver
        run: echo "version=1.0.0" >> $GITHUB_OUTPUT
  deploy:
    needs: build
    steps:
      - run: echo ${{ needs.build.outputs.version }}

12. What is needs keyword?

Defines job dependency.

deploy:
  needs: build

Deploy starts only after build completes.

13. How do you run jobs in parallel?

By not defining dependencies.

jobs:
  test
  scan
  build

All run simultaneously.

14. How do you cache dependencies?
- uses: actions/cache@v4

Example:

- uses: actions/cache@v4
  with:
    path: ~/.m2
    key: maven-cache

Benefits:

Faster builds
Reduced downloads
15. What are artifacts?

Files generated by workflow and stored after execution.

Upload:

- uses: actions/upload-artifact@v4

Download:

- uses: actions/download-artifact@v4

Examples:

JAR files
Reports
Test results
16. How do you schedule a workflow?

Using cron.

on:
  schedule:
    - cron: '0 1 * * *'

Runs daily at 1 AM UTC.

17. How do you define environment variables?

Workflow level:

env:
  APP_ENV: prod

Job level:

jobs:
  build:
    env:
      JAVA_HOME: /usr/lib/jvm/java-17

19. What are reusable workflows?

One workflow can call another workflow.

Example:

uses: company/shared-workflows/.github/workflows/build.yml@main

Benefits:

Reusability
Standardization
Reduced duplication
20. What is matrix strategy?

Run jobs against multiple environments.

strategy:
  matrix:
    os:
      - ubuntu-latest
      - windows-latest

Runs job on both operating systems.

Advanced Level

22. How do you authenticate to AWS securely?

Recommended:

OIDC Authentication
permissions:
  id-token: write

Benefits:

No AWS keys stored
Temporary credentials
More secure

Avoid:

AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY

where possible.

23. What is GitHub OIDC?

OpenID Connect integration between GitHub and AWS.

Flow:

GitHub Runner
↓
OIDC Token
↓
AWS IAM Role
↓
Temporary Credentials
↓
AWS Access
